# Pet Match AI
## Flutter · Android-first · Архитектура и соответствие ТЗ

Краткий документ для проверки: что реализовано, как устроен проект и за счёт чего обеспечивается качество.

## 1. Реализация требований ТЗ

1. Экранный flow реализован: `Welcome -> Intro -> Questionnaire -> Result -> Breed Details -> Gallery`.
2. Анкета поддерживает все типы вопросов: `single_choice`, `multiple_choice`, `dynamic_options/search_select`.
3. Для сессии реализован resume-flow: повторный вход продолжает текущий прогресс.
4. Реализованы состояния загрузки, ошибок и повтора действия.
5. Результаты совместимости отображаются полноценно: основная рекомендация и альтернативы.

## 2. Архитектура проекта

1. Применена Clean Architecture:
   - `data` — источники, DTO, мапперы, репозитории;
   - `domain` — сущности, use-cases, контракты;
   - `presentation` — экраны, виджеты, Cubit.
2. Слой `core` содержит общую инфраструктуру: DI, сеть, токены UI, компоненты дизайн-системы.
3. Навигация централизована через `go_router`.
4. Внедрение зависимостей — `get_it`.

## 3. Технологический стек

1. Flutter 3.x / Dart 3.x.
2. State management: `flutter_bloc` (Cubit).
3. Сеть: `dio` + interceptors.
4. Навигация: `go_router`.
5. DI: `get_it`.
6. Локальное хранение сессии: `SharedPreferences`.

## 4. Качество UI и UX

1. Введена единая дизайн-система: токены + shared-компоненты (`UiButton`, `UiCard`, `UiStateView`).
2. CTA-поведение унифицировано между ключевыми экранами.
3. В анкете реализован предсказуемый submit-flow с явной индикацией загрузки.
4. Переходы между экранами плавные и единообразные.
5. Верхние панели и базовые отступы выровнены для визуальной консистентности.

## 5. Надёжность и обработка ошибок

1. Ошибки типизированы (`AppFailure`) и корректно отображаются в UI.
2. Добавлены таймауты на критические сетевые операции.
3. Реализован retry-поток для пользовательских сценариев ошибок.
4. Обработка неожиданных исключений не оставляет экран в бесконечной загрузке.

## 6. Тестирование

1. Покрыты ключевые слои:
   - роутер;
   - shared UI-компоненты;
   - Cubit анкеты;
   - use-cases и мапперы.
2. `flutter analyze` — без замечаний.
3. `flutter test` — зелёный прогон по затронутым и регрессионным наборам.

## 7. Итог

Проект соответствует целям тестового задания: чистая архитектура, последовательный пользовательский сценарий, качественная обработка состояний и ошибок, а также подтверждённая стабильность через анализатор и автоматические тесты.
